# Strike Alert Belgium

Live strike and construction/roadwork tracking for STIB/MIVB, NMBS/SNCB, and Brussels
Airport, with browser push notifications and a NL/FR/EN dashboard. Deployed to Vercel
so it works from your phone regardless of whether your PC is on.

## How it works

- **NMBS/SNCB** — [iRail](https://docs.irail.be) `/disturbances` API (public, no key).
  Also tags scheduled engineering works separately (`type: "planned"`) from unplanned
  disturbances, which is what feeds the Construction tab for this source.
- **STIB/MIVB** — the "Travellers Information" JSON API on STIB's own open-data portal,
  [data.belgianmobility.io](https://data.belgianmobility.io) (public, no key).
- **Brussels Airport** — no public disruption API exists and the airport's own site
  blocks automated requests, so this is covered via keyword-filtered scans of Belgian
  news RSS feeds (VRT, RTBF, Bruzz) for "Brussels Airport" + strike mentions. Strikes
  only — no construction tracking for the airport.

The dashboard has two tabs/categories:
- **Strikes** — all three sources, filtered to items matching strike-related keywords
  (`staking`/`grève`/`strike` and inflections) in `lib/sources/news.ts`'s
  `matchesStrikeKeywords`.
- **Construction** — STIB + NMBS only, filtered to planned works/roadwork/diversions
  (STIB via `Works`/`Travaux`/`Werken` keyword match, NMBS via iRail's `planned` type).

Notifications are a **separate opt-in per category** — enabling construction alerts
doesn't turn on strike alerts and vice versa. This matters because construction volume
is much higher than strikes (STIB alone reports 300+ ongoing works messages at any
time): each poll run sends **one summarized notification per category** (e.g. "12 new
construction updates") rather than one notification per event, so a busy poll cycle
doesn't flood anyone's phone.

New events are stored in a Postgres database (Vercel Storage, via Neon).

## Deployment (production)

The app is deployed to Vercel at **https://strike-alert.vercel.app**.
Three things had to be configured in Vercel/GitHub for it to run unattended:

1. **Postgres database** — Vercel project → Storage tab → create a Postgres database
   (Neon) → connect it to the project. Vercel injects `DATABASE_URL` automatically;
   no code change needed.
2. **VAPID keys** — Vercel project → Settings → Environment Variables → add:
   - `VAPID_PUBLIC_KEY`
   - `VAPID_PRIVATE_KEY`
   (values come from your local `.env.local`, generated by `npm run generate-vapid-keys`)
3. **Scheduled polling** — `.github/workflows/poll.yml` runs every 10 minutes and hits
   `<your-deployed-url>/api/cron/poll`. It needs one repo secret set at
   github.com/<you>/Strike-Alert → Settings → Secrets and variables → Actions:
   - `POLL_URL` = your deployed URL (e.g. `https://strike-alert.vercel.app`, no trailing slash)

Once all three are set, redeploy (Vercel redeploys automatically on every push to `main`).

### Gotchas hit during initial setup (in case this project is ever reimported)

- **Framework Preset must be "Next.js"**, not "Other" or "Node.js" — Vercel's import
  screen didn't auto-detect it correctly the first time. Wrong preset builds
  "successfully" but every route 404s. Check Settings → General → Build and
  Deployment → Framework Preset.
- **Deployment Protection must be off** (Settings → Deployment Protection → Disabled).
  It defaults to gating every URL behind a Vercel login, which silently breaks both
  phone access and the GitHub Actions poller (they get redirected to
  `vercel.com/sso-api` instead of reaching the app).

## Using it from your phone

Open the deployed URL in your phone's browser, click **Enable notifications**, and
allow the permission prompt. On Android Chrome this works directly; on iOS Safari you
generally need to "Add to Home Screen" first (iOS only delivers web push to installed
PWAs, not regular Safari tabs).

## Local development

```bash
npm install
npm run generate-vapid-keys   # one-time: writes push notification keys to .env.local
```

Add the same `DATABASE_URL` from your Vercel Postgres database to `.env.local` (copy
it from Vercel's dashboard) so local dev hits the same database as production. Then:

```bash
npm run dev
```

To manually trigger a poll locally: `npm run poll` or `GET /api/cron/poll` while the
dev server runs.

### Optional: local always-on copies (superseded by the Vercel deployment)

Earlier in development, before deploying, this project ran entirely on this PC via:

- `scripts/start-server.bat`, launched at login via a shortcut in the Windows Startup
  folder (`shell:startup`), serving the dashboard at `localhost:3000`.
- A Windows Scheduled Task ("Strike Alert Poll") polling every 10 minutes via
  `scripts/poll.ts`.

These aren't needed anymore now that Vercel + GitHub Actions handle both jobs — the
dashboard and notifications now work independent of this PC. You can safely remove
the "Strike Alert Poll" scheduled task (`Unregister-ScheduledTask -TaskName "Strike Alert Poll"`)
and delete the Startup shortcut if you'd rather not run a redundant local copy.

## Notes / known limitations

- Notifications require the site to have been opened at least once in the browser/
  device used, to register the service worker and grant permission — this is a
  browser requirement, not something the app can bypass.
- The STIB and Brussels Airport sources were discovered by hand during development;
  if either changes its API/site structure, `lib/sources/stib.ts` or
  `lib/sources/airport.ts` will need updating.
- No third-party accounts are required for push notifications itself (Firebase,
  OneSignal, etc.) — VAPID keys are self-generated; the only accounts involved are
  Vercel (hosting + Postgres) and GitHub (code + scheduled polling), both free tier.

## Colour Partner (offline colour tool)

A separate, standalone mini-app lives in `public/colors/` — plain HTML/JS, no build step,
unrelated to the strike tracker. Pick a colour and it shows its complementary,
split-complementary, triadic, tertiary-neighbour (±30°) and square partners, on either the
additive light (RGB) wheel or the traditional paint (RYB) wheel, with hex, console hue,
RGB %, RGBW % and CMY % for each.

- Open **https://strike-alert.vercel.app/colors/index.html** once, then "Add to Home
  Screen". Its own service worker (`public/colors/sw.js`, scoped to `/colors/`) caches
  everything, so it works with no signal afterwards.
- When changing any file in `public/colors/`, bump `VERSION` in `public/colors/sw.js` so
  installed copies pick up the update.
- **Android APK:** `android/` wraps the same files in a native WebView app (no internet
  permission needed). `.github/workflows/android.yml` builds it on GitHub Actions whenever
  `public/colors/` or `android/` changes, and publishes `ColourPartner.apk` to the
  **"Colour Partner (latest)"** release. Open that release on your phone, download the APK,
  and allow "install unknown apps" when prompted. Builds are signed with the committed
  `android/app/colour-partner.keystore`, so new versions install over old ones.
